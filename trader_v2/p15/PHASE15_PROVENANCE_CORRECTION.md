## 2. Equivalence verification

**Method.** Strategy sections 1–6 were extracted from both files — everything before the line
`g(i) => str.tostring(array.get(K, i))`, which begins the output layer — then comments and blank
lines were stripped and the results diffed.

**Result.** Normalised: 478 lines (canonical) against 459 lines (executed). The diff contains
**three differences, all inside section 6 (detector verification)**:

```
<     bool tie = false                                  (+ the loop that sets it)
<         if na(pv3H) ... array.set(K, 34 / K, 33, ...)  ; if tie -> array.set(K, 35, ...)
<         if na(pv3L) ... array.set(K, 34 / K, 33, ...)  ; if tie -> array.set(K, 35, ...)
```

**Classification.** `K33`, `K34`, `K35` and the `tie` local are **write-only diagnostics**. No
decision anywhere in the program reads them; the canonical build only displays them as table
rows D33/D34/D35, and `tie` exists solely to gate the `K35` write. They cannot affect strategy
behaviour.

**Strategy-bearing lines are identical.** Verified identical: all fifteen inputs in the same
order (so the `in_0 … in_14` mapping is preserved), the 5m sweep engine, the LTF pivot detector,
CHOCH, the zero-tolerance CHOCH retest, BOS + displacement with CHOCH-pivot exclusion, FVG
selection, the fill and R-band test, the outcome model, the arm block, `SP`, `RB`, and the fold
boundaries `FB` / `FC` / `FE`.

Beyond the three diagnostic sites, the files differ only in comments and in the section-7 output
layer (table structure and ledger header text).

**Behavioural equivalence is established.**

## 4. Experiments A and B — validity

**A and B results remain valid and are not rerun.** They are preserved unchanged.

The reasons, as decided:

1. The same executed build produced every recorded result.
2. The strategy-bearing sections of that build were verified identical to the intended V53.
3. The only differences are write-only diagnostics and output.
4. The control arm and every experimental arm ran under that one artifact, with only the intended
   input changed between cells.
5. Experiment B's own integrity audit confirmed `dispMin` was the only strategy-bearing variable
   moving across its arms — sweeps, CHOCH and CHOCH retests were bit-identical in all four arms,
   cell by cell.
6. The diagnostic 2.50 → 2.00 round-trip probe was excluded from the dataset and remains excluded.

Rerunning A or B would not increase scientific validity; it would only create a second sample.

### Experimental definitions — unchanged by the correction

The definitions are exactly as pre-registered; the provenance correction did not redefine them.

- **C1** — CHOCH retest proximity = 0.10 × relevant LTF ATR.
  Old: `hitR = isLong ? l <= L : h >= L`.
  New: `hitR = isLong ? l <= L + tol : h >= L - tol`, `tol = 0.10 × ATR(14)` on the LTF,
  obtained via `request.security_lower_tf` and used **only** for this proximity test. The FVG
  fill test remains exact.
- **D1** — allow the CHOCH pivot to be used as the BOS reference if it is the most recent valid
  opposing pivot. Old: CHOCH pivot excluded, falling back to the previous pivot. New: included.
- **E1** — use the first qualifying FVG created by the displacement sequence after BOS, rather
  than requiring the displacement candle itself to be the middle candle. Bounded by the existing
  `dispWait = 12` chart-bar deadline measured from the sweep bar; no new parameter.
- **F1** — stop at the raw sweep extreme, with no ±0.20 × 5m ATR expansion.
- **G1** — use the first confirmed eligible opposing pivot after the sweep, latched, rather than
  rolling the CHOCH reference forward.

### Assertion expectations, carried forward unchanged

- **D1**: assertion A22 (BOS pivot ≠ CHOCH pivot) is **expected to be non-zero by construction**.
  It is retained and reported, never disabled. All other assertions must read 0.
- **E1**: A24 (BOS bar == displacement bar) is evaluated only on the first scan bar, where it
  keeps its original meaning, and must still read 0. All other assertions must read 0.
- **G1**: counter 4 changes meaning — it now counts how often a roll *would* have occurred — and
  is reported as such. A21 and A32 remain valid and must read 0.
- **C1, F1**: all assertions remain valid and must read 0.
